# 消息模板变量使用教程

## 1. 变量列表

| 变量名 | 说明 | 适用场景 | 默认值 |
|--------|------|----------|--------|
| `{{title}}` | 通知标题 | 所有通知 | "测试通知" |
| `{{task_name}}` | 任务名称 | 定时任务、测试执行 | "未知任务" |
| `{{task_type}}` | 任务类型 | 定时任务 | "API测试"/"UI自动化"/"APP自动化" |
| `{{module}}` | 模块名称 | 所有通知 | "测试平台" |
| `{{status}}` | 执行状态 | 测试执行 | "成功"/"失败"/"部分成功" |
| `{{status_text}}` | 执行状态文本 | 所有通知 | "执行成功"/"执行失败" |
| `{{execution_time}}` | 执行时间 | 定时任务 | 当前时间 |
| `{{success}}` | 是否成功 | 所有通知 | "是"/"否" |
| `{{start_time}}` | 开始时间 | 测试执行 | 当前时间 |
| `{{end_time}}` | 结束时间 | 测试执行 | 当前时间 |
| `{{duration}}` | 执行时长 | 测试执行 | "0秒" |
| `{{total_cases}}` | 用例总数 | 测试执行 | 0 |
| `{{passed_cases}}` | 通过用例数 | 测试执行 | 0 |
| `{{failed_cases}}` | 失败用例数 | 测试执行 | 0 |
| `{{error_cases}}` | 错误用例数 | 测试执行 | 0 |
| `{{skipped_cases}}` | 跳过用例数 | 测试执行 | 0 |
| `{{pass_rate}}` | 用例通过率 | 测试执行 | "0%" |
| `{{coverage_rate}}` | 用例覆盖率 | 测试执行 | "0%" |
| `{{project_name}}` | 所属项目 | 测试执行 | "默认项目" |
| `{{environment_name}}` | 所属环境 | API测试 | "默认环境" |
| `{{creator}}` | 任务创建者 | 定时任务 | "系统" |
| `{{executor}}` | 执行人 | 测试执行 | "系统" |
| `{{tester}}` | 测试人员 | 测试执行 | "系统" |
| `{{begin_time}}` | 开始时间 | 测试执行 | 当前时间 |
| `{{runtime}}` | 执行时长 | 测试执行 | "0秒" |
| `{{all}}` | 用例总数 | 测试执行 | 0 |
| `{{fail}}` | 失败用例数 | 测试执行 | 0 |
| `{{skip}}` | 跳过用例数 | 测试执行 | 0 |
| `{{report_url}}` | 详细报告链接 | 测试执行 | "#" |
| `{{config_name}}` | 配置名称 | 测试通知 | "默认配置" |


## 3. 变量使用说明

### 3.1 变量优先级

1. **实际值**：如果系统中存在对应的值，会使用实际值
2. **默认值**：如果系统中不存在对应的值，会使用默认值
3. **空值**：如果变量不存在且没有默认值，会显示为空字符串

### 3.2 变量适用场景

| 通知类型 | 适用变量 |
|----------|----------|
| 定时任务通知 | `{{title}}`, `{{task_name}}`, `{{task_type}}`, `{{status_text}}`, `{{execution_time}}`, `{{success}}`, `{{config_name}}` |
| API测试执行 | 所有变量 |
| UI自动化执行 | 所有变量 |
| APP自动化执行 | 所有变量 |
| 测试用例评审 | `{{title}}`, `{{project_name}}`, `{{executor}}`, `{{start_time}}`, `{{status_text}}` |

### 3.3 注意事项

1. **变量格式**：所有变量必须使用 `{{变量名}}` 格式，区分大小写
2. **平台限制**：不同平台对消息格式有不同限制
   - 邮件：支持 HTML 格式
   - 飞书/企业微信/钉钉：支持 Markdown 格式
   - 通用 Webhook：支持 JSON 格式
3. **变量替换**：系统会自动替换模板中的变量为实际值
4. **默认值**：当变量值为空时，会使用默认值
5. **特殊字符**：如果变量值包含特殊字符，系统会自动进行转义

## 5. 常见问题

### 5.1 变量不显示或显示为原始格式

**原因**：变量名拼写错误或大小写不匹配
**解决**：检查变量名是否正确，确保使用 `{{变量名}}` 格式，区分大小写

### 5.2 部分变量值为空

**原因**：对应的数据不存在
**解决**：系统会自动使用默认值，或在模板中使用条件判断

### 5.3 消息格式不正确

**原因**：使用了平台不支持的格式
**解决**：根据不同平台的格式要求调整模板

### 5.4 测试通知和实际通知内容不一致

**原因**：测试通知使用简化模板，实际通知使用完整模板
**解决**：测试通知仅用于验证配置是否正确，实际通知会包含完整的测试结果数据

## 6. 最佳实践

1. **模板设计**：
   - 保持模板简洁明了
   - 重点突出关键信息
   - 使用适当的格式和样式

2. **变量使用**：
   - 只使用必要的变量
   - 了解变量的适用场景
   - 考虑变量的默认值

3. **平台适配**：
   - 根据不同平台的特点设计模板
   - 测试不同平台的显示效果
   - 优化移动端显示

4. **错误处理**：
   - 测试模板的变量替换
   - 检查特殊字符的处理
   - 确保模板在各种情况下都能正常显示

通过合理使用消息模板变量，可以创建更加个性化和信息丰富的通知内容，提高团队的工作效率和测试质量。

### 2.2 模板渲染
位置：`backend/apps/scheduler/task_executor.py` - `_render_notification_template()`

```python
def _render_notification_template(template_content, context):
    """渲染通知模板"""
    content = template_content
    for key, value in context.items():
        placeholder = f"{{{{{key}}}}}"
        content = content.replace(placeholder, str(value) if value is not None else '')
    return content
```

### 2.3 邮件通知
位置：`backend/apps/scheduler/task_executor.py` - `send_notification()`

邮件通知使用配置的邮件模板或默认模板，支持：

### 2.4 Webhook通知
位置：`backend/apps/scheduler/task_executor.py` - `send_notification()`

Webhook通知支持自定义模板或默认模板：
- 自定义模板：使用 `_render_notification_template()` 渲染
- 默认模板：使用预定义的Markdown格式

## 4. 通知流程

### 4.1 API测试定时任务
1. 执行测试套件 → `execute_test_suite()`
2. 返回执行结果（包含测试统计数据）
3. 构建通知上下文 → `_build_notification_context()`
4. 发送邮件通知（使用完整上下文变量）
5. 发送Webhook通知（支持自定义模板）

### 4.2 UI自动化定时任务
1. 执行UI测试 → `execute_ui_test_suite()`
2. 返回执行结果
3. 构建通知上下文 → `_build_notification_context()`
4. 发送邮件通知
5. 发送Webhook通知

### 4.3 APP自动化定时任务
1. 执行APP测试 → `execute_app_test_suite()`
2. 返回执行结果
3. 构建通知上下文 → `_build_notification_context()`
4. 发送邮件通知
5. 发送Webhook通知

## 6. 变量使用说明

### 6.1 变量优先级

1. **实际值**：如果系统中存在对应的值，会使用实际值
2. **默认值**：如果系统中不存在对应的值，会使用默认值
3. **空值**：如果变量不存在且没有默认值，会显示为空字符串

### 6.2 变量适用场景

| 通知类型 | 适用变量 |
|----------|----------|
| 定时任务通知 | `{{title}}`, `{{task_name}}`, `{{task_type}}`, `{{status_text}}`, `{{execution_time}}`, `{{success}}`, `{{config_name}}` |
| API测试执行 | 所有变量 |
| UI自动化执行 | 所有变量 |
| APP自动化执行 | 所有变量 |
| 测试用例评审 | `{{title}}`, `{{project_name}}`, `{{executor}}`, `{{start_time}}`, `{{status_text}}` |

### 6.3 注意事项

1. **变量格式**：所有变量必须使用 `{{变量名}}` 格式，区分大小写
2. **平台限制**：不同平台对消息格式有不同限制
   - 邮件：支持 HTML 格式
   - 飞书/企业微信/钉钉：支持 Markdown 格式
   - 通用 Webhook：支持 JSON 格式
3. **变量替换**：系统会自动替换模板中的变量为实际值
4. **默认值**：当变量值为空时，会使用默认值
5. **特殊字符**：如果变量值包含特殊字符，系统会自动进行转义
6. **模板类型**：
   - 邮件：支持纯文本和HTML格式
   - Webhook：支持Markdown格式
7. **自定义模板**：Webhook通知支持使用自定义模板，模板ID在机器人配置中指定
8. **时间格式**：所有时间字段格式为 `YYYY-MM-DD HH:MM:SS`
9. **时长格式**：时长格式为 "X分Y秒" 或 "Y秒"

## 8. 常见问题

### 8.1 变量不显示或显示为原始格式

**原因**：变量名拼写错误或大小写不匹配
**解决**：检查变量名是否正确，确保使用 `{{变量名}}` 格式，区分大小写

### 8.2 部分变量值为空

**原因**：对应的数据不存在
**解决**：系统会自动使用默认值，或在模板中使用条件判断

### 8.3 消息格式不正确

**原因**：使用了平台不支持的格式
**解决**：根据不同平台的格式要求调整模板

### 8.4 测试通知和实际通知内容不一致

**原因**：测试通知使用简化模板，实际通知使用完整模板
**解决**：测试通知仅用于验证配置是否正确，实际通知会包含完整的测试结果数据

1. **模板设计**：

3. **平台适配**：

## 12. 模板配置说明

### 12.1 邮件模板配置

邮件模板配置在 `ScheduleConfig` 模型中通过 `notification_template` 字段关联：

- 如果配置了邮件模板，系统会使用该模板
- 如果未配置，系统会使用默认邮件模板（`is_default=True` 的邮件模板）
- 如果没有默认模板，系统会使用内置的默认内容

### 12.2 Webhook模板配置

Webhook模板配置在机器人配置中通过 `notification_template_id` 字段关联：

- 如果配置了模板，系统会使用该模板渲染消息
- 如果未配置，系统会使用内置的默认Markdown格式

### 12.3 测试通知

测试通知（通过前端"测试发送"按钮触发）使用固定消息，不读取模板配置。这是为了快速验证通知配置是否正确。
